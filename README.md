# Стенд оценки языковых моделей

Приложение для оценки и сравнения локальных языковых моделей **без доступа к интернету** по методике статьи
«Метод оценки качества и сравнения больших языковых моделей на основе нечётких множеств»
(правила Мамдани + взвешенное симметрическое среднее Маклорена, ВСММ).

- **Этап 1.** Оценка по внешним тестовым наборам: MMLU-ru, RuBia (предвзятость и токсичность), время отклика.
- **Этап 2.** Оценка по своим наборам: выбор варианта, короткий ответ, структурированный вывод (JSON),
  развёрнутый ответ (эксперт и/или модель-судья).
- **Этап 3.** Дообучение (LoRA/QLoRA через mlx-lm) на своей предметной области и сравнение с исходной моделью.

## Запуск

1. В LM Studio включите сервер: вкладка Developer → Start Server (порт 1234).
2. Двойной щелчок по `start.command` (или `bash start.command` в Терминале).
   При первом запуске создаётся окружение `.venv`, пакеты ставятся **из `vendor/wheels` без сети**.
   Откроется браузер: http://127.0.0.1:8501. Остановка — Ctrl+C в Терминале.

Приложение слушает только 127.0.0.1; библиотеки HF работают в офлайн-режиме (`HF_HUB_OFFLINE=1`).

## Страницы

| Страница | Назначение |
|---|---|
| Главная | Состояние подключений, офлайн-режима, последние прогоны |
| Модели | Подключения (LM Studio, OpenAI-совместимые: mlx_lm.server, Ollama, llama.cpp; «Демо»), модели для оценки, связь «исходная ↔ дообученная» |
| Тестовые наборы | Библиотека внешних и своих наборов; редактор заданий (таблица и карточка), паспорт и шаблон запроса, проверка корректности, выборки «оценка / отладка / обучение», импорт (JSONL, CSV, Excel, Parquet) и выгрузка, история изменений |
| Нечёткая модель | Конструктор: показатели и нормирование, термы, правила (из списков, таблицей решений или текстом), проверка полноты, пробный расчёт |
| Прогон | Пробный (N заданий) или полный прогон; остановка и продолжение; оценка моделью-судьёй; журнал |
| Результаты | Показатели с 95 % доверительными интервалами, по категориям, графики, сравнение двух моделей (Макнемар / бутстреп), просмотр ответов, проверка экспертом, согласие судьи и эксперта |
| Сводная оценка | Профиль показателей, границы нормирования, k; ВСММ, центроид, взвешенная сумма, геометрическое среднее, TOPSIS, парето-фронт; чувствительность (±20 %); ранжировки экспертов (W и τ Кендалла); отчёт в Word |
| Диалог | Разговор с одной или двумя моделями бок о бок; сохранение ответа как примера для дообучения или задания набора |
| Дообучение | Обучающий набор из своих заданий, проверка утечек в выборку «оценка», LoRA на MLX с графиком потерь, подключение адаптера или объединение в модель LM Studio |
| Система | Оформление рисунков, самопроверка офлайн-режима, настройки, журналы, резервная копия базы |

## Рисунки и таблицы для статьи

Все рисунки строятся в оформлении для Word: Times New Roman 12 пт, десятичная запятая, заданная ширина (по умолчанию
16 см), подпись «Рис. N. …». Меню «Сохранить рисунок» — PNG 300 dpi (вставляется в Word в натуральную величину,
шрифт остаётся 12 пт), SVG, PDF и .docx (рисунок и подпись отдельным абзацем). Таблицы сохраняются в Word
(«Таблица N – …»), Excel и CSV. Номера и подписи запоминаются. Есть чёрно-белый вариант (штриховка, типы линий).

## Показатели

Точность (с ДИ), устойчивость (всего и по видам возмущений: опечатки, перестановка вариантов, переформулировка),
соблюдение формата, предпочтение позиции ответа, F1 для коротких ответов, корректность JSON / соответствие схеме /
верные поля, оценки эксперта и судьи, индекс предвзятости, доля выборов стереотипа, отказы, токсичность и средняя
вероятность токсичности, время отклика (медиана, 90-й процентиль, разброс), время до первого токена, скорость
генерации, длина ответа, объём весов и доля памяти стенда, прирост занятой памяти и время загрузки модели.

## Данные

```
benchmarks/<код>/benchmark.json   паспорт набора (тип, шаблон запроса, проверка, показатель)
benchmarks/<код>/items.jsonl      задания (id, поля по типу, category, split, weight, tags, note)
config/fuzzy/*.json               нечёткие модели (article_v5 — модель статьи)
config/profiles/*.json            профили: какие наборы дают какие показатели
workspace/bench.db                ответы, оценки, прогоны (SQLite)
workspace/training/               задания на дообучение, адаптеры, примеры из диалога
vendor/wheels | models | datasets офлайн-комплект
legacy/                           прежний пульт и его результаты (перенесены в базу)
```

Ответ хранится вместе с текстом запроса: при правке задания старые ответы на него перестают учитываться,
остальные сохраняются. Прогон пропускает уже полученные ответы с теми же настройками.

## Командная строка

```bash
./.venv/bin/python -m pytest -q                                  # проверки (в т. ч. табл. 5 статьи)
./.venv/bin/python -m tools.import_external rebuild --n 200      # пересобрать MMLU-ru и RuBia из vendor/datasets
./.venv/bin/python -m tools.import_external samples              # образцы своих наборов
bash tools/make_offline_bundle.sh                                # (с сетью) обновить офлайн-комплект
```

## Дообучение

Базовая модель — папка в формате MLX (например, `~/.lmstudio/models/lmstudio-community/gemma-4-E4B-it-MLX-4bit`).
Модели GGUF через MLX дообучать нельзя. После обучения:
- «Сервер с адаптером» — `mlx_lm.server --adapter-path …`, модель сразу доступна для прогонов и диалога;
- «Объединить» — `mlx_lm.fuse` в `~/.lmstudio/models/local/<имя>`, модель появляется в LM Studio.

Задания выборки «обучение» не участвуют в прогонах по выборке «оценка»; перед обучением проверяются утечки
(совпадения и пересечения текста с заданиями оценки).
